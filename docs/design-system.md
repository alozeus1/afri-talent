# Frontend design tokens and dark mode

Source: `frontend/src/app/globals.css`. Light values live on `:root`, dark
values on `html.dark`. The `.dark` class is set before first paint by an
inline script in `app/layout.tsx` and kept in sync by `ThemeProvider`
(`lib/theme-context.tsx`). Tokens are exposed as Tailwind v4 utilities
through `@theme inline`.

## Use these, not raw palette classes

| Role | Utility | Light | Dark |
|---|---|---|---|
| Page background | `bg-canvas` | #f7f7f5 | #0b0b0e |
| Card / panel | `bg-surface` | #ffffff | #131316 |
| Raised (popover, inner card) | `bg-surface-raised` | #ffffff | #1b1b20 |
| Inset / tile | `bg-surface-sunken` | #f3f3f1 | #0f0f12 |
| Hover / muted fill | `bg-surface-muted` | #ecece8 | #222228 |
| Hairline border | `border-line` | #e4e4e0 | #2a2a31 |
| Control border | `border-line-strong` | #d0d0ca | #3b3b44 |
| Primary text | `text-fg` | #18181b | #f4f4f5 |
| Secondary text | `text-fg-secondary` | #3f3f46 | #d4d4d8 |
| Muted text / captions | `text-fg-muted` | #5b5b66 | #a1a1aa |
| Primary button fill | `bg-primary` / `hover:bg-primary-hover` + `text-primary-fg` | #047857 / white | #047857 / white |
| Brand text, links | `text-primary-text` | #047857 | #34d399 |
| Status text | `text-success` / `text-warning` / `text-danger` / `text-info` | 700 shades | 300-400 shades |
| Status fill | `bg-*-soft` + `border-*-line` | 50 shades | 12% tint |
| Focus ring | `ring-focus` | #059669 | #34d399 |

Elevation: `shadow-xs`, `shadow-card`, `shadow-raised`, `shadow-overlay`.
Radius: `rounded-[var(--radius-control)]` (controls), `--radius-card`,
`--radius-panel`. Motion: `--ease-standard`, `--transition-fast` (150ms),
`--transition-base` (220ms). `prefers-reduced-motion` disables animation.

### Contrast (WCAG AA)

Measured pairs: `fg`/surface is 17.7:1 light and 16.9:1 dark. `fg-secondary`
is 10.4:1 and 12.6:1. `fg-muted` is 6.7:1 light (6.0:1 on sunken) and 7.2:1
dark (5.9:1 on surface-muted). White on `primary` is 5.5:1. Status text
colours are at least 5.0:1 light and at least 6.7:1 dark. Every pair meets
4.5:1 for body text.

## Shared components

`components/ui/button.tsx`, `badge.tsx`, `input.tsx`, `select.tsx`,
`textarea.tsx`, `card.tsx`, `tabs-2.tsx`, `empty-state.tsx` and `skeleton.tsx`
use only tokens. Every `Button` variant (`primary`, `secondary`, `outline`,
`ghost`, `danger`) is legible on any surface in both themes.

## Legacy palette classes (dark-compat layer)

The codemod `scripts/codemod-semantic-colors.mjs` rewrote neutral classes
across `src/` to tokens. Examples: `text-gray-900` became `text-fg`, `bg-white`
became `bg-surface` and `border-gray-200` became `border-line`. Hued
light-only classes remain, such as `bg-amber-50`, `text-blue-900` and
`border-emerald-200`. For these, `src/styles/dark-compat.css` (generated by
`npm run tokens:dark-compat`) remaps them under `.dark`, but only on elements
that do not declare their own `dark:` variant. Treat it as a safety net. New
code should use tokens. After adding legacy classes, re-run the generator,
because it only emits rules for classes found in `src/`.

## Verifying

`frontend/e2e/local-docker/visual-contrast.spec.ts` loads key pages in light
and dark mode at desktop and mobile widths and fails on axe `color-contrast`
violations:

```
APP_BASE_URL=http://localhost:3000 API_BASE_URL=http://localhost:4000 \
  npx playwright test -c playwright.local-docker.config.ts visual-contrast
```
